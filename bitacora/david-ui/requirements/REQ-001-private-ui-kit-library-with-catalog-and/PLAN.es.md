# Plan — Paquete de kit de interfaz personal con catálogo público

Esqueleto (planificación colaborativa, fase Esqueleto). Solo hitos y subplanes; las tareas se definen subplan por subplan junto con el propietario.

## Enfoque
Monorepositorio público con npm workspaces `dav033/david-ui`: `packages/ui` es `@dav033/david-ui` (GitHub Packages, Changesets + Actions), `apps/catalog` es el catálogo público con Next.js 16 en Vercel, que consume el paquete mediante el workspace. Primero el paquete; después el catálogo, y cada familia posterior se incorpora al paquete y al catálogo al mismo tiempo. Las piezas que necesite el catálogo se agregan al paquete en el mismo cambio (R4). D-003.

### M1 — Base del paquete: monorepo, identidad y publicación
El monorepo público supera npm run verify, el paquete se publica en GitHub Packages a partir de un changeset integrado y una aplicación nueva con Next 16 + Tailwind 4 lo instala y compila con el tema del kit.

Cubre R1, R2, R4, R5, R10, R11.

  Tareas de SP-1 (borrador para confirmación del propietario). Resoluciones del propietario del 2026-10-26 (aclaraciones de SPEC para SP-1): (A1) sin archivo LICENSE de código abierto, todos los derechos reservados: el README indica uso personal y cada `package.json` declara `"license": "UNLICENSED"`; (A2) los agentes hacen commits directamente en `main` y se hace push de `main` integrada a `origin` (acción de producción autorizada por el propietario, restricciones de SPEC). Entradas: `gh` con sesión iniciada como dav033 y ámbitos `repo` y `workflow`; ninguna otra entrada para SP-1.
  Contratos producidos: toolchain@1 (T1), upstream-compat@1 (T2), dependency-set@1 (T3), catalog-manifest@1 (T4), kit-only-guard@1 (T5). Prueba de integración T6, auditoría T7. DAG: T1 → T2 → T3 → {T4, T5} → T6 → T7.
