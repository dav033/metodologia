## Requirements (all with tests, TDD)
1. Ports: `GitPort` protocol (rev_parse, merge_tree with explicit merge base, commit_tree, update_refs atomic CAS,
   tree_digest over paths, diff_paths, add/remove worktree for candidate workspaces) and a SQLite WAL `Store` at a path
   the caller passes (one DB per run). An in-memory fake `GitPort` for module tests.
2. Subplan versions: `publish_subplan_version(plan_id, plan_revision, subplan_id, commit, line_base, contracts,
   evidence)` → `SP@vN` with an immutable ref `refs/subplans/<plan>/<SP>/v<N>` created only if absent (CAS from zero);
   manifest JSON with sha256; idempotent for an identical request; a different commit for an existing N is refused.
3. Compositions: `build_candidate(plan_id, members: {SP: vN})` starting from `refs/compositions/<plan>/current` (or a
   given run base), folding each **changed** member's own delta (`line_base → version commit`) in deterministic order
   with `merge-tree --merge-base`; textual conflict → candidate `rejected`, class `git_text_conflict`, paths listed,
   `current` untouched. Candidate ref `refs/compositions/<plan>/candidates/C<N>`. `open_workspace(candidate)` returns a
   temporary worktree path; `close_workspace` removes it. `publish(candidate, verdicts)` only when every required verdict
   is PASS: one atomic transaction writes `refs/compositions/<plan>/C<N>` and moves `current` CAS `C<N-1> → C<N>`;
   any failure leaves `current` exactly as before. `reject(candidate, evidence)`.
4. Selective propagation `propagate(change, plan_subplans, evidence)` returning distinct operations `reverify |
   reintegrate | audit | adapt_contract | modify | reimplement` per affected consumer, by the rules of ENGINE-F4 §1. A
   test proves an ancestry-only change never yields more than `reverify`; `reimplement` only from an explicit
   demonstrated finding input.
5. Evidence binding: `EvidenceKey(tree_digest, contracts, environment)`; `reusable(old, new)` true only on equality /
   equivalence proof (equal relevant-path digest + contract hashes + environment).
6. Demonstrations as tests (fake git and real git): `C1 = {S1@v1, S2@v1, S3@v1}` published; `S1@v2` → `C2` candidate
   → PASS → published, S2/S3 versions untouched; a forced incompatibility (failing verdict) leaves `current == C1`
   and C1 intact; a textual conflict leaves C1 intact; crash between candidate creation and publish (simulate by
   failing `update_refs`) leaves C1 intact and a retry is idempotent.
7. Never push, never touch `main`/branches/HEAD of the repository, never write the working tree of the main checkout:
   refs under `refs/subplans/` and `refs/compositions/` only; candidate worktrees under a directory the caller passes.
