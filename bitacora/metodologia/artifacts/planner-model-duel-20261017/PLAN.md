## Matched setup

- Freeze current improved Planner role, its four private skills, methodology references and schema from the verified nine-source bundle. Supply the same complete instructions to each route.
- Preserve each source archive hash and SPEC bytes; extract separate copies per cell in a retained scratch workspace. No expected plans, oracle candidates or other outputs enter that workspace.
- Fresh sessions; no source writes. Claude: safe/restricted mode, Read/Grep/Glob tools only, plan permission mode, no session persistence. Codex: user-config/rules ignored, read-only sandbox, web disabled, read-only shell inspection instructed. Native tool affordances differ and are a stated limitation.
- Tools may inspect files but not execute tests/builds, install, mutate git, browse or delegate. Shared task override delegates deterministic validation to the host and allows explicit decision-gated provisional drafts when the request leaves owner choices unresolved.
- One call per effective account; at most two accounts concurrently. Sol/Astra order alternates by case. No automatic fallback, retries, repair turns or additional review-model calls.
- Common output: exactly PLAN.md and PLAN.json filename-labeled fenced blocks, schema1.2.0, revision1, maximum8 independently actionable tasks. One900s deadline plus30s CLI watchdog allowance per cell.

## Evidence and adjudication

1. Capture before/after account quota, native versions, final text, reported numeric usage, observed model IDs and read-tool invocation metadata. Never retain raw private thinking text or full raw streams. Missing/failed telemetry remains unknown.
2. Hash source workspace contents before/after each call; abort a lane on source mutation, model mismatch, CLI failure or timeout. Capture first-response format failures rather than silently repairing them.
3. Run a frozen standalone bt_planner validate/check/report from the host, mapping repository evidence to the exact inspected copy. Record errors/warnings and schema/Markdown disagreement separately from semantic plan quality. No product test success is claimed.
4. Shuffle complete candidate plans into route-hidden views. Coordinator judges the 13 frozen substantive expectations as full/partial/missing, with exact task/prose evidence and caveats. Evaluate unsafe assumptions, unspecified algorithms/interfaces, false existing-code claims, missing dependency gates, rollback and verification readiness. Do not inflate coverage by covers labels alone; do not invent a weighted intelligence score.
5. A structurally valid plan can be unsafe; an invalid first response can contain useful content. Report these axes separately. These three cases and one sample per cell cannot prove general model superiority. Native hidden prompts/tokenizers, tools, context reuse/cache and reasoning effort interpretation differ.
