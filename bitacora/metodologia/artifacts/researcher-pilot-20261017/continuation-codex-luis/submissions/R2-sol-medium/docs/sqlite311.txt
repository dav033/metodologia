02131 | How to use the connection context manager
02132 | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
02133 | 
02134 | A :class:`Connection` object can be used as a context manager that
02135 | automatically commits or rolls back open transactions when leaving the body of
02136 | the context manager.
02137 | If the body of the :keyword:`with` statement finishes without exceptions,
02138 | the transaction is committed.
02139 | If this commit fails,
02140 | or if the body of the ``with`` statement raises an uncaught exception,
02141 | the transaction is rolled back.
02142 | 
02143 | If there is no open transaction upon leaving the body of the ``with`` statement,
02144 | the context manager is a no-op.
02145 | 
02146 | .. note::
02147 | 
02148 |    The context manager neither implicitly opens a new transaction
02149 |    nor closes the connection.
02150 | 
02151 | .. testcode::
02152 | 
02153 |    con = sqlite3.connect(":memory:")
02154 |    con.execute("CREATE TABLE lang(id INTEGER PRIMARY KEY, name VARCHAR UNIQUE)")
02155 | 
02156 |    # Successful, con.commit() is called automatically afterwards
02157 |    with con:
02158 |        con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))
02159 | 
02160 |    # con.rollback() is called after the with block finishes with an exception,
02161 |    # the exception is still raised and must be caught
02162 |    try:
02163 |        with con:
02164 |            con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))
02165 |    except sqlite3.IntegrityError:
02166 |        print("couldn't add Python twice")
02167 | 
02168 |    # Connection object used as context manager only commits or rollbacks transactions,
02169 |    # so the connection object should be closed manually
02170 |    con.close()
