02396 | .. _sqlite3-connection-context-manager:
02397 | 
02398 | How to use the connection context manager
02399 | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
02400 | 
02401 | A :class:`Connection` object can be used as a context manager that
02402 | automatically commits or rolls back open transactions when leaving the body of
02403 | the context manager.
02404 | If the body of the :keyword:`with` statement finishes without exceptions,
02405 | the transaction is committed.
02406 | If this commit fails,
02407 | or if the body of the ``with`` statement raises an uncaught exception,
02408 | the transaction is rolled back.
02409 | If :attr:`~Connection.autocommit` is ``False``,
02410 | a new transaction is implicitly opened after committing or rolling back.
02411 | 
02412 | If there is no open transaction upon leaving the body of the ``with`` statement,
02413 | or if :attr:`~Connection.autocommit` is ``True``,
02414 | the context manager does nothing.
02415 | 
02416 | .. note::
02417 |    The context manager neither implicitly opens a new transaction
02418 |    nor closes the connection. If you need a closing context manager, consider
02419 |    using :meth:`contextlib.closing`.
02420 | 
02421 | .. testcode::
02422 | 
02423 |    con = sqlite3.connect(":memory:")
02424 |    con.execute("CREATE TABLE lang(id INTEGER PRIMARY KEY, name VARCHAR UNIQUE)")
02425 | 
02426 |    # Successful, con.commit() is called automatically afterwards
02427 |    with con:
02428 |        con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))
02429 | 
02430 |    # con.rollback() is called after the with block finishes with an exception,
02431 |    # the exception is still raised and must be caught
02432 |    try:
02433 |        with con:
02434 |            con.execute("INSERT INTO lang(name) VALUES(?)", ("Python",))
02435 |    except sqlite3.IntegrityError:
02436 |        print("couldn't add Python twice")
02437 | 
02438 |    # Connection object used as context manager only commits or rollbacks transactions,
02439 |    # so the connection object should be closed manually
02440 |    con.close()

02645 | Transaction control
02646 | ^^^^^^^^^^^^^^^^^^^
02647 | 
02648 | :mod:`!sqlite3` offers multiple methods of controlling whether,
02649 | when and how database transactions are opened and closed.
02650 | :ref:`sqlite3-transaction-control-autocommit` is recommended,
02651 | while :ref:`sqlite3-transaction-control-isolation-level`
02652 | retains the pre-Python 3.12 behaviour.
02653 | 
02654 | .. _sqlite3-transaction-control-autocommit:
02655 | 
02656 | Transaction control via the ``autocommit`` attribute
02657 | """"""""""""""""""""""""""""""""""""""""""""""""""""
02658 | 
02659 | The recommended way of controlling transaction behaviour is through
02660 | the :attr:`Connection.autocommit` attribute,
02661 | which should preferably be set using the *autocommit* parameter
02662 | of :func:`connect`.
02663 | 
02664 | It is suggested to set *autocommit* to ``False``,
02665 | which implies :pep:`249`-compliant transaction control.
02666 | This means:
02667 | 
02668 | * :mod:`!sqlite3` ensures that a transaction is always open,
02669 |   so :func:`connect`, :meth:`Connection.commit`, and :meth:`Connection.rollback`
02670 |   will implicitly open a new transaction
02671 |   (immediately after closing the pending one, for the latter two).
02672 |   :mod:`!sqlite3` uses ``BEGIN DEFERRED`` statements when opening transactions.
02673 | * Transactions should be committed explicitly using :meth:`!commit`.
02674 | * Transactions should be rolled back explicitly using :meth:`!rollback`.
02675 | * An implicit rollback is performed if the database is
02676 |   :meth:`~Connection.close`-ed with pending changes.
02677 | 
02678 | Set *autocommit* to ``True`` to enable SQLite's `autocommit mode`_.
02679 | In this mode, :meth:`Connection.commit` and :meth:`Connection.rollback`
02680 | have no effect.
02681 | Note that SQLite's autocommit mode is distinct from
02682 | the :pep:`249`-compliant :attr:`Connection.autocommit` attribute;
02683 | use :attr:`Connection.in_transaction` to query
02684 | the low-level SQLite autocommit mode.
02685 | 
02686 | Set *autocommit* to :data:`LEGACY_TRANSACTION_CONTROL`
02687 | to leave transaction control behaviour to the
02688 | :attr:`Connection.isolation_level` attribute.
02689 | See :ref:`sqlite3-transaction-control-isolation-level` for more information.
02690 |
