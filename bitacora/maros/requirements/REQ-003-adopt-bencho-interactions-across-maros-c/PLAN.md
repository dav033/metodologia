# Plan — REQ-003 — Adopt Bencho interactions across Maros CRM

## Approach
Audit all `maros-next/src/app/**/page.tsx` routes and shared interactive shell, then record every workflow, considered Bencho/Motion Primitives block, decision, guardrail, and verification in `INTERACTION-INVENTORY.md`. Adapt source blocks per feature rather than installing Bencho or replacing sound controls wholesale. Keep shadcn/Radix as the core component system and use Motion Primitives only as a supplementary source of purposeful motion; add the Motion runtime only if selected components require it. Add one cross-section command palette that consolidates task/note search and permission-filtered navigation, then improve existing interactions in vertical slices; touch `maros-nest` only if an accepted capability proves it needs API behavior or persistence.

- Cover all 59 current `page.tsx` routes, including static pages and redirect routes in the inventory; mark which ones actually have interactive UI. The public routes are `/login`, `/about`, `/privacy-policy`, and `/p/[token]` plus its states. Do not mount authenticated actions on public routes.
- Preserve business rules, persisted data, permissions, navigation, validation, retry/error states, keyboard and touch operation, and reduced-motion preferences. For public notes, keep the token out of Referer headers and retain read-only/password/expiry behavior.
- Use purposeful motion for action feedback, state transitions, loading, and spatial continuity where the inventory shows a workflow benefit. Honor `prefers-reduced-motion`; avoid continuous decorative motion and animation-only status.
- Reuse existing React/Radix/shadcn, `@dnd-kit`, form, and search capabilities where they fit. Add dependencies only when a selected block requires one and justify the source/lockfile.
- Consider Motion Primitives for selected app-oriented animated controls. The project declares MIT and beta status; audit each copied block, dependencies, accessibility, and SSR behavior. Magic UI is available but mainly targets landing pages, so use it only if a specific route warrants a block.
- Adapt copied blocks to Maros design tokens and Spanish UI copy for any new interface; retain MIT notices for substantial copied source. Do not copy Bencho branding or licensed photos.
- Do not push, merge, deploy, mutate production data, or send external messages. Do not add or run test suites; use the listed static checks and source review.
- Before code work, create a matching `feat/req-003-bencho-interactions` branch in each touched repository; current worktrees are clean on the prior feature branch.
