## Incident: production DB connection exhaustion (2026-11-12 ~09:39 COT)

- Symptom: production (demo-decoracion.vercel.app, commit dc64f74) returned 503 `BASE_NO_DISPONIBLE`; Postgres `53300 remaining connection slots are reserved for roles with the SUPERUSER attribute` / `too many clients already`.
- Cause: `req021-db` on advin had `max_connections=100`; 87 were idle `pictures_app` sessions via `pictures-db-gateway` (wsproxy, `@neondatabase/serverless`), orphaned by frozen Vercel instances. Each instance holds several pools (rag `max:20`, one `createAccountPool()` `max:4` per route module — 14 route files on main). The ring-training gallery (300 examples, thumbnails per request) multiplies instances.
- Done: `ALTER ROLE pictures_app SET idle_session_timeout='90s'` (was unset); terminated 58 orphaned idle sessions; `ALTER SYSTEM SET max_connections=200` + `docker restart req021-db`. Rollback: `ALTER ROLE pictures_app RESET idle_session_timeout`; `ALTER SYSTEM RESET max_connections` + restart.
- Code fix (commit 34fe65c46 on main, branch `fix/db-connection-exhaustion`): `createPgPool` calls `attachDatabasePool` (@vercel/functions 3.8.0, pinned; 3.10.x pulls zod 4.6 into the app) when `VERCEL` is set; app code shares one `getAccountPool()` per process (26 call sites; `createAccountPool` kept for scripts, max 8, idle 5 s); RAG pool max 20->10, idle 20 s->5 s; 57P05 retried for reads. Checks: eslint on changed files and `tsc --noEmit` passed; tests not run (owner preference).
- Follow-up commit 98566583d: the shared account pool also retries single reads on terminated connections (old deployment showed 57P05 failures from thawed instances).
- Worst case per instance is now 18 connections to req021-db (8 accounts + 10 RAG; the advisor pool goes to Supabase), against 200 slots and a 90 s server-side idle cut.
