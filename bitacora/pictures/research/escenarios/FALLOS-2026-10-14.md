# Scenario sweep failures, 2026-10-14 (REQ-014 T22)

Runs: seed 1 (1970/2000 pass) and random seed 259600 (1959/2000 pass), 2000 scenarios each, sha 6e1388af.
Every failure is `banda_conteo` (balloon count outside the PARIDAD-2026-10-09 band, tolerance 3 balloons). No build
exceptions, no overlaps, nothing outside the room, no non-determinism, no budget overruns, no dishonest notices.
Failures are findings: no engine behaviour or band was changed to hide them. All 8 distinct classes are already in
`CLASES_PERMITIDAS` of `scripts/test/test-escenarios-matriz.ts` (measured earlier), so the fast test does not catch drift beyond that list.
Reproduce one scenario: `escenarioDe(<seed>, <index>)` from `scripts/escenarios/generador.ts`; reports hold a minimal repro per class
(`scripts/escenarios/salidas/informe-s<seed>-n2000.json` when run with the default output).

## Root cause 1: ring (aro_circular) under-filled, 41 scenarios total (seed 1: 18, seed 259600: 23)

Classes: `aro_circular:media:bajo` (11 / 15), `:lujosa:bajo` (6 / 6), `:sencilla:bajo` (1 / 2). The organic ring counts about
13.8 / 16.7 / 10.9 balloons per metre (media / lujosa / sencilla) against bands 19-26 / 24-40 / 13-20. Cause: `PERFIL_ARO` in
`calibracion-organica.ts` trims the R-5 filler of the ring. Minimal repro, seed 1, E-00016: aro_circular 1.66 m, organica_fina, one colour (no density, default media).
Open question: is the engine or the band wrong? PARIDAD has a Python count for the ring; the engine is deliberately lower.

## Root cause 2: organic column thickness assumption, 20 scenarios (seed 1: 11, seed 259600: 9) plus 1 over-count

Classes (under-count): `columna:media:bajo` 6/6, `columna:lujosa:bajo` 0/2, `columna:sencilla:bajo` 0/1,
`columna_asimetrica:{lujosa,media,sencilla}:bajo` 4/8. The PARIDAD band assumes the default 0.7 m thickness
(`GROSOR_ORGANICO_POR_DEFECTO_M`) but the generator draws widths 0.4-1 m; thinner columns hold fewer balloons per metre of
height. Repro, seed 1, E-00907: columna 1.17 m high, 0.66 m wide, organica_fina.
Over-count: `columna_asimetrica:lujosa:sobre` (seed 1, E-00580: 2.39 x 0.92 m): thicker tube gives more balloons per metre than the band.
Diagnosis: the band is per metre of axis and ignores thickness, so this class is likely a band-model gap, not an engine bug.

## Root cause 3: short garland rounding, 2 scenarios (seed 1: 1, seed 259600: 1)

`guirnalda:media:bajo` (seed 1, E-01844: largoM 1.27 organica_fina) and `guirnalda:sencilla:bajo` (seed 259600). The 3-balloon
tolerance does not cover rounding on very short pieces. Likely a band-tolerance gap (tolerance should scale with length).

## Coverage gaps (not failures)

About 2600 pieces per run have no count band (`sin_banda`), so they are neither pass nor fail: techo_globos, pared_densa,
racimo_pared, bouquet, centro_mesa, figura, arco_asimetrico organica_fina, guirnalda solo_grandes and similar. The
count invariant covers only the structures PARIDAD measured. Counts for these structures are unchecked.
