# Plan — REQ-014 — 72h marathon — autonomous product development

## Approach
The owner's 72-hour brief (`PROMPT-MARATHON-3-DAYS.md`) is executed by the marathon supervisor as one task per fresh
headless session (Haiku first, escalation per brief §5; `level: architecture` tasks start on Opus). Order: W1 first
(REQ-007 Phase 5 from `d2590cd4`, split into merge → ops → mapping → route → integration design → UI → regression),
then W2 scenario matrix + property tests, W5 local Claude provider, W6 repositories, W3 BalloonBuilder quick wins, W4
training harness, W7 dossier — interleaved, with three ship tasks. The plan **grows by itself**: PM reviews
(decorator / customer, alternating), completeness critics and scenario sweeps each append 3–6 evidence-backed task
lines tagged `origin: T<n>` and their verify proves it. Alternative considered: one long `/loop` session as the brief
describes — rejected for 72 h because a clean session per task avoids context rot and the supervisor enforces caps,
retries and usage-limit waits.
