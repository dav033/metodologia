## Why the card titles are still Spanish (read-only check, nothing written)

- The route now calls `construirContenidoVisible` (T10.452), which for `en` loads English names with
  `SELECT source_id, spanish_source, english_text FROM textos_ingles WHERE kind = 'campo_decoracion' AND field = 'name'`
  and replaces a card's `titulo` only when `spanish_source` equals the Spanish title. T10.452 deliberately stopped
  overwriting `tematica` (the subtitle) with the English name.
- **The test database's `textos_ingles` table exists but is empty** (0 rows of any kind; checked with a `READ ONLY`
  transaction that was rolled back). The table is filled by `npm run textos:sembrar` (`scripts/textos/sembrar.ts`) from
  `data/textos-ingles/*.json`; the verify recipe's prepare steps do not run it, and it has not been run against the
  REQ-021 test database.
- The candidate's `data/textos-ingles/ideas.json` (448 names + 448 descriptions) **has English names for 5 of the 6
  cards**: `asistente:deco-real-09-images-24` "Pink and gold birthday garland", `asistente:deco-real-29-arco-link-o-loon-fucsia-tulipanes`
  "Fuchsia link arch with tulip bouquet", `asistente:deco-real-05-arco-organico-…` "Pink and rose gold half-arch for
  Mom", `asistente:deco-real-11-images-26` "Pastel pink, lilac and aquamarine garland", `asistente:deco-real-18-sddefault`
  "Pastel pink and gold garland". "Arreglo de flores con globos para modelar" has no entry. The subtitles ("Rosa y
  dorado", "Baby shower niña", …) have no English source in that data.
- So with the seed applied, 5 of 6 titles would likely render in English (not verified here: the id and the exact
  Spanish-source match were not exercised against a seeded table); one title and all subtitles would stay Spanish.
