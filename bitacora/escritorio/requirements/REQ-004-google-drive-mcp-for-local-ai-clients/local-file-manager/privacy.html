Política de privacidad

Última actualización: 16 de octubre de 2026

1. Servicio

El Gestor local de archivos es una integración personal de un solo usuario. Un servidor MCP se ejecuta en el computador de su propietario y conecta clientes MCP locales con su cuenta de Google Drive. No es un producto de Google ni un servicio público de MCP. Esta página es estática e informativa.

2. Datos de Google a los que accede

Cuando el propietario autoriza la integración, su permiso de Drive permite acceso de lectura y escritura a los archivos de su cuenta. Según la operación solicitada, el servidor puede procesar contenido de archivos, nombres, identificadores, tipos, enlaces, metadatos y permisos. El permiso de OAuth es amplio y no se limita a archivos creados por esta integración.

Las operaciones disponibles pueden buscar y leer archivos, crear o editar archivos, cambiar permisos, compartirlos y moverlos a la papelera recuperable. La lista de herramientas no ofrece el borrado permanente.

3. Uso y circulación de los datos

Los datos de Google se usan únicamente para realizar la operación que solicita el propietario a través de un cliente MCP local. El servidor envía las solicitudes necesarias a las API de Google y devuelve los resultados al cliente local que las pidió. No se venden los datos ni se usan para publicidad o para entrenar modelos de forma independiente.

El propietario elige el cliente de IA. Ese cliente puede transmitir la solicitud y los resultados a su proveedor de modelos, sujeto a las condiciones y controles de privacidad de ese proveedor. El servidor MCP no controla las prácticas del cliente ni de su proveedor.

Google recibe las solicitudes de API y aplica sus propias condiciones y políticas al servicio de Drive. El contenido creado o modificado permanece en Drive, conforme a las acciones del propietario.

4. Almacenamiento y conservación

El servidor procesa las solicitudes en el computador del propietario. Los tokens de OAuth y el archivo de credenciales se guardan allí con permisos de acceso restringidos al usuario del sistema. El sitio público no recibe ni almacena esos tokens ni contenido de Drive.

El servidor mantiene registros locales de depuración. Pueden contener marcas de tiempo, nombres de operaciones, dirección de correo de la cuenta, identificadores o nombres de archivos, enlaces, parámetros de operación y detalles de errores. Se guardan en el computador con permisos restringidos; no se ha configurado un plazo automático de eliminación.

5. Sitio informativo y DNS

Las páginas informativas se sirven desde Vercel. Como cualquier servicio web, el proveedor de alojamiento puede procesar datos técnicos de las visitas, como dirección IP, navegador y solicitudes, para entregar y proteger el sitio; consulte la política de privacidad de Vercel. El contenido de Drive y los tokens de OAuth del servidor local no se envían a Vercel.

Si se usa DuckDNS para el subdominio, su política indica que puede recibir del proveedor de inicio de sesión el nombre, nombre de usuario, correo electrónico y foto de perfil autorizados; también puede procesar la IP usada para iniciar sesión, el correo, el token propio de acceso a su servicio DNS, la IP de destino y los datos técnicos de navegación. Consulta la política de privacidad de DuckDNS (actualizada el 28 de enero de 2020). DuckDNS no recibe el contenido de Drive ni los tokens OAuth del servidor local.

6. Control y seguridad

El servidor escucha solo en la interfaz local del computador; esta página no publica el servicio MCP. Los permisos de Drive se usan en nombre de la cuenta que autorizó el acceso. El propietario puede revocar el acceso desde su cuenta de Google y borrar los archivos locales de credenciales y registros. La revocación no elimina archivos de Drive.

Privacy policy — English summary

Last updated: October 16, 2026

Service. The Local File Manager is a single-user personal integration. Its MCP server runs on the owner's computer and connects local MCP clients to the owner's Google Drive. It is not a Google product or a public MCP service. This website is static information only.

Google data and use. The OAuth grant allows broad read/write access to Drive files, including content, names, IDs, metadata, links, and permissions as needed for a requested operation. Available operations search, read, create, edit, share, change permissions, and move files to recoverable trash; permanent deletion is not exposed. Data is used only to fulfill the owner's requests, sent to Google's Drive APIs as needed, and returned to the local AI client that requested it. The selected client may send prompts and results to its model provider under that provider's own terms. This integration does not sell Google data, use it for advertising, or independently train models on it.

Storage and logs. OAuth credentials and tokens are stored on the owner's computer with user-restricted file permissions. The public website does not receive them or Drive content. Local debug logs may include timestamps, operation names, account email, file IDs or names, links, operation parameters, and error details. They remain on the computer; no automatic deletion period is configured.

Website and DNS providers. Vercel hosts these static pages and may process ordinary technical visit data; see Vercel's privacy policy. If DuckDNS is used for the subdomain, its policy says it may receive authorized sign-in profile details (name, username, email, and profile picture), sign-in IP, email, its own DNS-service access token, target IP, and technical browsing data; see its privacy statement (last updated January 28, 2020). DuckDNS does not receive Drive files or the local MCP's OAuth tokens.

Control and contact. The server listens only on the owner's computer. The owner can revoke Google access and remove local credentials and logs. Questions: david.theran03@gmail.com.
